# LIVE(실거래) 활성화·정지·복구

LIVE는 **사용자의 의도적인 활성화로만** 켜집니다. API 키를 넣거나 앱을 재시작하는 것만으로는 켜지지 않고, 정지 상태도 재시작으로 풀리지 않습니다. 몇 주의 모의운용이나 수익성 입증은 요구하지 않지만, 아래 기술 점검은 반드시 통과해야 합니다. 활성화 이후 설정 범위 안의 주문은 건별 승인 없이 실행됩니다.

## 0. 준비 — 업비트(코인)

1. 업비트에서 **서브포켓**을 만들고 실험 원금(예: 300,000원)만 메인포켓에서 이전합니다(사용자가 직접, 이 프로그램은 자금 이동을 하지 않음).
2. 그 서브포켓으로 Open API 키 발급: 권한 **[자산조회] [주문조회] [주문하기]만**. 출금·입금·포켓관리·자산이전 권한은 주지 마세요. 맥북의 공인 IP를 허용 IP로 등록.
3. `.env`에 `UPBIT_LIVE_ACCESS_KEY`, `UPBIT_LIVE_SECRET_KEY` 입력.
4. 같은 코인을 다른 프로그램·수동으로 같은 포켓에서 거래하지 마세요. 봇이 모르는 미체결 주문이나 설명되지 않는 잔고 변화가 보이면 해당 계좌 자동 주문이 차단됩니다.

## 0'. 준비 — KIS(주식, 선택)

1. KIS Developers에서 앱키 발급, 가능하면 봇 전용 계좌 사용. 모의투자 키로 `broker_sandbox` 모드에서 먼저 확인 권장.
2. `.env`의 `KIS_LIVE_APP_KEY/APP_SECRET/ACCOUNT_NO/ACCOUNT_PRODUCT`(모의는 `KIS_SANDBOX_*`).
3. 설정에서 `markets.kr_stock`(또는 `us_stock`) `enabled=true`, `allocation_krw`(합계 ≤ 원금 한도) 지정. 미국 주식은 계좌에 USD가 있어야 하며 자동 환전은 하지 않습니다.

## 1. 활성화 절차

```bash
bash scripts/macos/aifund.sh --mode live selftest                       # 실행무결성 자체검증(24시간 유효)
bash scripts/macos/install_launchd.sh --mode live                       # live 모드 서비스(아직 실주문 없음)
bash scripts/macos/aifund.sh --mode live live check crypto --ack-no-withdraw
bash scripts/macos/aifund.sh --mode live live enable crypto --ack-no-withdraw --confirm "LIVE crypto upbit-main"
```

`check`/`enable`이 확인하는 것: 모드=live, 시장 설정, 실계좌 어댑터, 출금 권한 없는 키(사용자 확인), 자체검증, 계좌 인증·잔고 조회, 상품 상태·최소 주문 금액, 시계 오차, 주문 가능 금액, **거래소 주문 검증 API**(업비트 `/v1/orders/test`, 실제 주문 없음), 외부 미체결 주문 없음, 대사, 상태불명 주문 없음.
활성화 순간: 현재 거래소 보유분 중 봇 장부에 없는 수량을 **기존 보유분**으로 기록(봇이 매도하지 않음) → 대사 → 활성화 기록(시장·계좌·허용 종목·한도·운용 설정의 해시).

대시보드 **제어** 화면에서도 같은 절차(체크박스 + 확인 문구)로 켤 수 있습니다.

## 2. 운영 중 자동 차단(신규 위험 증가 중지, 매도는 가능한 범위에서 유지)

- 설정(한도·종목·계좌·운용 설정) 변경 → LIVE '재확인 필요'(모든 실주문 중지) → 1번 절차 다시.
- 일손실 30,000원 도달 → 그날(KST) 신규 매수 중지 / 최대 낙폭 30% → 수동 해제 전까지 중지(`제어` 화면의 '낙폭 정지 해제', 확인 문구 필요).
- 시세·캔들 지연, 환율 지연(외화), 시계 오차, 스프레드 과대, 휴장, 인증 오류, 상태불명 주문, 대사 불일치, AI 정책(`hold_new_risk` 선택 시).

## 3. 정지(각각 설명된 일만 함)

| 동작 | 명령 | 하는 일 / 하지 않는 일 |
|---|---|---|
| 신규 매수 중지 | `aifund.sh --mode live halt crypto --reason "..."` / `resume crypto` | 위험 증가만 차단, 재시작해도 유지 / 보유·매도·미체결은 그대로 |
| 미체결 취소 | `aifund.sh --mode live cancel-open --market crypto` | 봇 주문만 취소 요청(거래소 확인 전까지 '취소 요청됨') / 보유분 매도 안 함 |
| 보유분 청산 | `aifund.sh --mode live liquidate crypto` (미리보기) → `--confirm "청산 crypto"` | 봇 장부 수량만 매수1호가 −0.3% 지정가 매도, 최대 3회 재호가, 신규 매수 중지 동시 설정 / 시장가 전량 매도 아님, 기존 보유분 제외, 최소 주문 미만 잔량은 남음 |
| LIVE 끄기 | `aifund.sh --mode live live disable crypto --reason "..."` | 이후 신규 실주문 차단 / 이미 낸 주문 취소는 별도(`cancel-open`) |
| 서비스 종료 | `stop.sh --mode live` | 신규 주문 중지·상태 기록 후 종료 / 거래소의 미체결 주문은 남아 있을 수 있음(다음 시작 시 대사) |

## 4. 장애 후 복구

- **상태불명(unknown) 주문**: 서비스가 거래소 조회로 자동 해소를 시도합니다(업비트: identifier 조회, KIS: 당일 주문 유일 매칭). 그동안 해당 계좌의 위험 증가 주문은 차단됩니다. KIS에서 후보가 여러 건이면 자동 연결하지 않으니 거래소 앱에서 주문을 확인하세요.
- **대사 불일치(recon_block)**: 대시보드에 불일치 내용과 해결 안내가 표시됩니다. 원인(수동 거래·다른 프로그램·외부 출금)을 정리한 뒤 `aifund.sh --mode live reconcile`. 봇 밖에서 생긴 보유가 정당한 기존 보유분이라면 `live baseline crypto --confirm "기준 재설정 upbit-main"`으로 명시적으로 다시 기록합니다.
- **인증 오류(auth_error)**: 키 만료(업비트 키는 1년)·IP 변경 확인 → 수정 후 계좌 확인이 성공하면 자동 해제.
- **DB 손상**: `stop` → `restore <백업> --yes` → 시작(대사 완료 전 신규 주문 금지).

## 5. 손실 제한에 대한 정확한 설명

손실 제한은 신규 위험 증가를 멈추는 운영 기준입니다. 가격 급변·거래소 장애·맥북 정지 상황에서 실제 손실이 한도를 넘지 않는다는 보증이 아닙니다. 로컬 손절은 거래소 서버에 걸린 보호 주문이 아니며, 맥북·네트워크가 멈추면 실행되지 않습니다.
